# Corrective RAG

An adaptive RAG pipeline built with [LangGraph](https://langchain-ai.github.io/langgraph/), running entirely on local models via [Ollama](https://ollama.com/) with [Tavily](https://tavily.com/) for web search.

The graph combines three patterns:

- **Adaptive RAG** — a router decides up front whether a question should hit the vector store or go straight to web search.
- **Corrective RAG** — retrieved documents are graded for relevance, and web search fills the gap when they fall short.
- **Self-RAG** — the generated answer is checked for grounding in the source documents and for whether it actually answers the question, with a bounded retry loop.

## Architecture

```
                      ┌──────────────┐
                      │ Route Question│
                      └──────┬───────┘
              vectorstore    │    websearch
             ┌───────────────┴───────────────┐
             ▼                               │
        ┌─────────┐                          │
        │ retrieve│                          │
        └────┬────┘                          │
             ▼                               │
     ┌────────────────┐   any doc irrelevant │
     │ grade_documents├──────────────────────┤
     └────────┬───────┘                      ▼
              │ all relevant           ┌────────────┐
              │                        │ web_search │
              │                        └──────┬─────┘
              ▼                               │
        ┌──────────┐ ◄────────────────────────┘
        │ generate │ ◄──────────────┐
        └────┬─────┘  not_supported │
             ▼                      │
   ┌───────────────────┐            │
   │ hallucination +   ├────────────┘
   │ answer grading    │
   └─────────┬─────────┘
             │ useful                not_useful
             ▼                      └──────────► web_search
            END
```

`graph.png` is a rendered version of the same graph, regenerated by `python -m graph.graph`.

### Routing decisions

| Check | Chain | Outcome |
|---|---|---|
| Is the question in-corpus? | `router` | `vectorstore` → retrieve, `websearch` → skip retrieval |
| Is each retrieved doc relevant? | `retriever_grader` | any `no` → set `web_response`, trigger web search |
| Is the answer grounded in the docs? | `hallucination_grader` | `false` → regenerate |
| Does the answer address the question? | `answer_grader` | `false` → web search for better sources |

The `generate → generate` loop is bounded by `MAX_RETRIES` in `graph/consts.py`. This matters: LangGraph's default recursion limit in this version is 10,007, so an unbounded grading loop would run for hours rather than failing fast.

## Requirements

- Python 3.13
- [Poetry](https://python-poetry.org/)
- [Ollama](https://ollama.com/) running locally with two models pulled:
  ```bash
  ollama pull gemma3:latest          # generation + all graders
  ollama pull nomic-embed-text:latest # embeddings
  ```
- A [Tavily](https://tavily.com/) API key for web search

## Setup

```bash
poetry install
```

Create a `.env` file in the project root:

```
TAVILY_API_KEY=your-key-here

# Optional — LangSmith tracing
LANGCHAIN_TRACING_V2=true
LANGCHAIN_API_KEY=your-key-here
LANGCHAIN_PROJECT=corrective-rag
```

Build the vector store. This scrapes three Lilian Weng blog posts (agents, prompt engineering, adversarial attacks on LLMs), chunks them, and embeds them into a local Chroma store at `chroma_db/`:

```bash
python -m graph.ingestion
```

This takes a few minutes — `unstructured` does the HTML parsing, and embedding runs in batches of 100. Re-running **appends**, so delete `chroma_db/` first if you want a clean rebuild.

## Usage

```bash
python main.py            # ask the question hardcoded in main.py
python -m graph.graph     # run the graph and regenerate graph.png
```

Or from Python:

```python
from graph.graph import fin

result = fin.invoke({"question": "What is agent memory?"})
print(result["answer"])
```

> **Run modules, not files.** `python graph/graph.py` fails with `'graph' is not a package` — running a file directly puts `graph/` on `sys.path`, so `graph` resolves to `graph.py` instead of the package. Use `python -m graph.graph`. In VS Code, press **Ctrl+F5** and pick a config from `.vscode/launch.json`; the plain ▶ button runs the file directly and will fail.

## Project layout

```
graph/
├── graph.py          StateGraph wiring, routing conditions, compiled app (`fin`)
├── state.py          GraphState TypedDict — the schema flowing between nodes
├── consts.py         node names, route names, MAX_RETRIES
├── ingestion.py      scrape → chunk → embed; exposes `retriever`
├── nodes/            graph nodes (retrieve, grade_documents, websearch, generate)
└── chains/           LLM chains (router, retriever_grader, hallucination_grader,
                      answer_grader, generations)
```

**Nodes vs chains:** a chain is a prompt piped into a model (`prompt | llm`). A node is a function that reads state, calls a chain, and returns the keys it changed. LangGraph merges those partial updates into the running state.

## State

```python
class GraphState(TypedDict):
    question: str          # the user's question
    answer: str            # the generated answer
    web_response: bool     # whether document grading triggered web search
    retrieved_docs: List[str]
    retries: int           # bounds the self-RAG regeneration loop
```

Two things to know when adding nodes:

- **`retrieved_docs` holds plain strings, not `Document` objects.** `retrieve` unwraps `.page_content` once; nothing downstream unwraps again. Any list going into a prompt needs `"\n\n".join(...)` first, or it renders as `['doc one', 'doc two']`.
- **Keys not in this schema are silently dropped.** A node returning `{"generation": ...}` when the schema says `answer` produces no error and no value. If you add state, add it here first.

## Notes

- All models run locally, so latency is dominated by Ollama. A typical query takes 5–9s; a regeneration loop roughly doubles it.
- Startup costs ~7s of imports, since the chains construct their Ollama clients and open Chroma at module level. It's paid once per process.
- The router prompt in `graph/chains/router.py` names the corpus topics explicitly. **If you change the URLs in `graph/ingestion.py`, update that prompt too** — otherwise the router won't know the new topics exist and will send those questions to the web.
- `chroma_db/` is generated and gitignored. Rebuild it with `python -m graph.ingestion`.
